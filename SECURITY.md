# Security policy

## Report a security hole privately

Don't open a public issue for a security problem. A public issue tells attackers about the hole before it's fixed.

Use GitHub's private form instead: [report a vulnerability](https://github.com/yusufcemaydin/yardstick-predict/security/advisories/new). Only the maintainers can see what you send.

Include:

- what the problem is, and what an attacker could do with it,
- the steps to make it happen,
- the version you tested.

You should hear back within 7 days. We'll tell you when it's fixed and credit you in the release notes, unless you'd rather stay anonymous.

## What counts

Please report anything that could:

- run code on someone's computer without their consent, for example through a model file or a saved run record,
- send a user's tasks, code or run history anywhere they didn't agree to,
- weaken the privacy guarantee on runs shared with the hosted service,
- leak API keys or other secrets.

Wrong forecasts aren't security problems. Report those with the "Forecast was way off" issue form.

## Supported versions

No version has been released yet. Once there are releases, security fixes go into the latest one.
